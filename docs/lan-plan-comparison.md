# 1대1 기획서 비교 및 LAN 베타 개발 현황

기준: 사용자가 제공한 `one-on-one-game-plan.md`와 v0.4.0.
개발 빌드: 0.5.0-beta.3. 준비 버튼 수정에 이어 장거리 게이지/조준 보정 축소, 점프 높이 30% 증가, 스틸 접촉 시간/범위와 블록 접촉 범위/팔 유지 시간을 확대했다. 득점 조건은 여전히 초록+실제 링 통과다. 두 맥북 모두 경기 규칙 버전 2의 같은 베타로 업데이트해야 한다. 이 문서는 실제 두 맥북의 Wi-Fi 검증 완료를 뜻하지 않는다.

이전 요청에 따라 Shift는 별도 달리기 자세 없이 속도만 변경한다. 기획서의 새 달리기 자세·팔을 따라 움직이는 복잡한 드리블은 이번 LAN 베타에서 추가하지 않았다. 기존 연습은 그대로 남기며 충전 중 점프·충전 이동 감속을 보완했다. 정식 대전 AI·인터넷 매칭·2대2·파울·자유투는 이 기획서에서도 첫 범위 밖이다.

## 구현 구조

- `GameTypes.swift`: 공통 키 의미, 유지 입력, 재전송 행동 명령, 방향.
- `GameSession.swift`: PlayerState/ActionSystem, 단일 소유자, 고정 60Hz 공식 경기.
- `LANNetwork.swift`: Bonjour, TCP 프레이밍, 로비, UDP 바인딩, 입력/스냅샷, 복구.
- `LANViews.swift`: 시작/로비/결과 메뉴, 입력 예측·표시 상태, 카메라·HUD.
- `LANTests.swift`: 규칙·입력·직렬화·실제 loopback 통신 검사.
- 기존 CourtDemo/CharacterMotion/BallPhysics/ShotPhysics/DefensePhysics/CourtGeometry의 연습·포즈·충돌 자산을 재사용한다. LAN 로직은 CourtDemo에 덧붙이지 않았다.

플레이어의 일반/점프슛은 초록 타이밍과 실제 하향 링 통과가 모두 필요하다. 로컬 표시만으로 성공을 확정하지 않는다. 양쪽의 X 릴리스는 동일한 방장 명령 처리 경로를 사용한다. 네트워크에는 초록 성공 여부를 보내지 않는다. TCP 제어는 길이 프레이밍+크기 상한을 사용하고 UDP는 1400바이트 이하를 목표/검사한다. 출력 숫자의 표시 정밀도를 0.001로 제한하며 판정은 방장의 원래 정밀도로 계산한다.

토큰 매칭은 다른 세션 데이터 혼입을 막기 위한 것이며 암호화된 인터넷 서비스나 계정 인증이 아니다. 신뢰할 수 있는 로컬 네트워크에서 테스트한다. IPv4 직접 연결도 네트워크 격리를 우회하지 않는다.

## 자동 검사와 실제 검증의 구분

내부 검사에는 다음이 포함된다.

- 이전 초록 경계/실패/림·백보드/2·3점/도약 위치/수비 연습 검사.
- 두 선수의 같은 스틸·블록·공중 리바운드, 충전 중 점프, 공격 방향, 점수 귀속.
- 3분/14초·중앙 재개·리바운드 공격 제한·마지막 슛·연장·경기 종료.
- 중복 X 릴리스, 오래된 경기·입력 epoch, 악성 이동 축, 데이터 크기·중복 스냅샷.
- 한글 문자로 생성한 이벤트의 물리 키 코드, C/Space/방향키, 메뉴 Return/Esc, 포커스 상실.
- 한 맥의 두 실제 네트워크 참가자: TCP/UDP 준비·로비·시작·이동·슛·점수·정지/재개·재연결·재경기·나가기.
- 양방향 20/50/100ms 수준 왕복 지연, 0~10ms 추가 지터, 전송 4개마다 1개 손실(25%) 주입.

이 검사는 **두 실제 맥북의 Wi-Fi·Bonjour·권한·방화벽·기종 검사를 대체하지 않는다.** ARM/Intel universal 컴파일과 임시 서명 검증은 하드웨어별 실제 플레이 검증과 다르다. 첫 LAN 리뷰 빌드이며 전체 기획 완료/정식 LAN 출시라고 표시하지 않는다.

## 두 맥북 테스트 절차

1. 두 맥북에서 같은 LAN 베타를 설치한다. 응용 프로그램의 `Full Court Stickman LAN Beta`를 실행한다. 기존 `Full Court Stickman` v0.4.0은 별도로 유지된다.
2. 같은 일반 Wi-Fi에 연결한다. 이 앱의 로컬 네트워크/방화벽 접근 안내가 나타나면 허용한다. 지원 OS에서 해당 설정이 없는 경우 방화벽/네트워크 격리 여부부터 확인한다.
3. 첫 맥: ‘같은 Wi-Fi 대전’ → 별칭/방 이름 → ‘방 만들기’.
4. 둘째 맥: ‘방 찾기’ → 같은 방 참가. 보이지 않으면 방장 화면의 IPv4:포트를 직접 입력한다.
5. 양쪽 ‘준비’ 후 방장이 ‘경기 시작’. 방장 오른쪽/참가자 왼쪽 방향으로 공격한다.
6. 먼저 방향키 이동·X 슛·득점 후 실점자 중앙 소유가 양쪽에서 같은지 확인한다.
7. 양쪽 C 스틸, Space+C 블록, 리바운드, Z 덩크, 충전 중 Space를 확인한다.
8. 한쪽 Esc/포커스 이동 → 두 사람 준비 → 방장 재개. 경기 시간이 정지 중 줄지 않아야 한다.
9. 3분을 끝까지 플레이하고 결과가 같은지 확인한다. 양쪽 재경기 선택 시 점수가 초기화되고 첫 공격권이 바뀌어야 한다.
10. 참가자 Wi-Fi를 잠깐 끊었다 복구한다. 정지·재연결·준비 재개를 확인한다. 10초 이상 실패/방장 종료는 경기 종료 안내가 나와야 한다.
11. 방장/참가자를 바꾸어 다시 검사한다. 두 맥의 macOS 버전·칩, 자동 발견/직접 연결 결과, 문제가 발생한 조작·양쪽 화면 차이를 기록한다. 개인 IP/별칭은 공개 이슈에 그대로 올릴 필요가 없다.

검증이 끝난 다음 정식 Homebrew cask에 승격하고, 리그/발 고정/고급 지연 보상을 이어서 개선한다.
